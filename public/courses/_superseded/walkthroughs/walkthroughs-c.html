# Kling Prompt Generator (v3.1 - Per-Scene Descriptions, Envato)

## What the AI Needs Per Scene to Generate the Best Prompt
1. What room is the start frame (Frame N)
2. What room is the end frame (Frame N+1)
3. What camera movement the student wants (push forward, pan right, etc.)
4. The two actual images (for spatial context)

## Flow

1. Student uploads property photos in walkthrough order (drag and drop)
2. N images appear as N-1 video cards (Frame 1 to 2, Frame 2 to 3, etc.)
3. Each card has a "Describe this scene" text input where the student writes 1-2 sentences:
   - What room Frame N is
   - What room Frame N+1 is
   - What camera movement they want
   Example: "Frame 1 is the front entrance, Frame 2 is the living room. Camera pushes forward through the front door into the living room."
4. Student clicks "Generate All Prompts"
5. The Superagent receives each card's description text + that card's two image URLs
6. For each card, generate the Kling 3.0 prompt by combining:
   - The student's description (rooms + camera movement intent)
   - The actual images (for spatial detail, what's visible, layout verification)
   - The anti-bounce template
   - The best Envato camera preset for the described movement
7. Write the generated_prompt and suggested_preset back to the PropertyImage record
8. Update the Property status to "Prompts Ready"
9. Each generated prompt appears directly under its video card

## Envato Camera Preset Selection Logic

- Forward movement through space (corridor, hallway, entering room) = "Dolly In"
- Backward movement (exiting room, pulling back) = "Dolly Out"
- Lateral movement left (panning across to left side) = "Pan Left"
- Lateral movement right (panning across to right side) = "Pan Right"
- Looking upward (stairs, high ceilings, second level) = "Tilt Up"
- Looking downward (stairs going down, looking at floor detail) = "Tilt Down"
- Rising above (balcony view, aerial transition) = "Crane Up"
- Descending (coming down stairs, lowering view) = "Crane Down"
- No movement, subject reveals within frame = "Static"
- Following a path alongside walls = "Tracking Shot"

## Anti-Bounce Language (baked into every prompt)

Every prompt MUST include: "Camera rigidly locked on professional tripod, no walking bounce, no vertical bobbing, no micro-jitter, gimbal-smooth only, constant linear speed."

## Prompt Template

[Preset] preset. Camera rigidly locked on professional tripod, no walking bounce, no vertical bobbing, no micro-jitter, gimbal-smooth only, constant linear speed. In one continuous motion, the camera [movement from student's description, enriched with spatial detail from viewing both images] from [room_type N] to [room_type N+1] as shown in the end frame. Maintain fixed spatial geometry, rigid walls and furniture, no warping, no distortion, no perspective stretch.

## Example

Card 1 description: "Frame 1 is the front entrance, Frame 2 is the hallway. Camera pushes forward through the front door into the hallway."

Generated prompt for Card 1:
Dolly In preset. Camera rigidly locked on professional tripod, no walking bounce, no vertical bobbing, no micro-jitter, gimbal-smooth only, constant linear speed. In one continuous motion, the camera pushes forward through the front entrance into the hallway, moving straight ahead until the hallway is visible as shown in the end frame. Maintain fixed spatial geometry, rigid walls and furniture, no warping, no distortion, no perspective stretch.

Card 2 description: "Frame 2 is the hallway, Frame 3 is the living room. Camera pans right from the hallway into the living room."

Generated prompt for Card 2:
Pan Right preset. Camera rigidly locked on professional tripod, no walking bounce, no vertical bobbing, no micro-jitter, gimbal-smooth only, constant linear speed. In one continuous motion, the camera pans right from the hallway into the open living room area, continuing until the living room space is fully visible as shown in the end frame. Maintain fixed spatial geometry, rigid walls and furniture, no warping, no distortion, no perspective stretch.

---
name: video-stitcher
description: Stitches multiple property walkthrough video clips (from Envato/Kling) into one final walkthrough video with smooth crossfade transitions between clips, using ffmpeg.
---

# Video Stitcher

Combines individual Envato-generated clips (one per scene/transition) into a single finished property walkthrough video.

## When to Use
Student has uploaded all their finished Envato clips back into their Base44 app's "Final Clips" section, one clip per scene (Clip 1: Frame 1 to 2, Clip 2: Frame 2 to 3, etc.). Student copies the prompt from the app and sends it to their Superagent in chat.

The student's message will look like:
"I have uploaded all my finished Envato video clips for [property address] into the Final Clips section. Each clip is matched to its scene (Clip 1: Frame 1 to 2, Clip 2: Frame 2 to 3, etc.). Please stitch all clips together into one final walkthrough video with smooth crossfade transitions between each scene, then send me the finished video."

## What This Skill Does
1. Reads all ListingClip records for the property from the app, ordered by sequence_order ascending
2. Downloads each clip video file into the sandbox
3. Normalizes all clips to 1920x1080, 30fps, h264/aac codec so they match perfectly
4. Stitches with crossfade (xfade) transitions between each consecutive clip (0.5 second default)
5. If crossfade fails or there are too many clips, falls back to hard cuts using ffmpeg concat
6. Outputs one final stitched mp4 file
7. Uploads the final video using upload_file to get a public URL
8. Saves the final video URL back to the Property record (final_video_url field)
9. Updates the property status to "Delivered"
10. Sends the student a download link via chat

## Step-by-Step Process (for the agent to follow)

### 1. Identify the property and gather clips
- Find the property by address from the student's message (search Property records)
- Use read_entities to get all ListingClip records for that property_id, sorted by sequence_order ascending
- Each record has: sequence_order, video_url, label (e.g. "Clip 1: Frame 1 to Frame 2")

### 2. Download clips
mkdir -p /app/conversations/<conv_id>/stitching/<property_slug>
cd /app/conversations/<conv_id>/stitching/<property_slug>
curl -L -o clip_01.mp4 "<video_url_1>"
curl -L -o clip_02.mp4 "<video_url_2>"
# repeat for all clips in order

### 3. Verify each clip is valid
for f in clip_*.mp4; do
  echo "Checking $f:"
  ffprobe -v error -show_entries format=duration -of csv=p=0 "$f"
done

### 4. Normalize clips (all clips must be same resolution, framerate, codec before xfade)
ffmpeg -i clip_01.mp4 -vf "scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2,setsar=1" -r 30 -c:v libx264 -crf 18 -preset medium -c:a aac -ar 44100 norm_01.mp4
# repeat for every clip

### 5. Get duration of each normalized clip (needed for xfade offset calculation)
ffprobe -v error -show_entries format=duration -of csv=p=0 norm_01.mp4
ffprobe -v error -show_entries format=duration -of csv=p=0 norm_02.mp4
# repeat for all normalized clips

### 6. Stitch with crossfade transitions (xfade filter)
For N clips with 0.5s crossfade, chain xfade filters. The offset for each xfade = cumulative duration of all previous clips minus (crossfade_duration times number of preceding xfades).

Example for 3 clips (each 5s, crossfade 0.5s):
ffmpeg -i norm_01.mp4 -i norm_02.mp4 -i norm_03.mp4 -filter_complex \
"[0:v][1:v]xfade=transition=fade:duration=0.5:offset=4.5[v01]; \
[v01][2:v]xfade=transition=fade:duration=0.5:offset=9[v012]; \
[0:a][1:a]acrossfade=d=0.5[a01]; \
[a01][2:a]acrossfade=d=0.5[a012]" \
-map "[v012]" -map "[a012]" -c:v libx264 -crf 18 -preset medium -c:a aac final_walkthrough.mp4

For more than 5 clips, process pairwise sequentially to avoid filter_complex getting too long.

### 7. Simpler fallback (hard cuts, no crossfade, more reliable for many clips)
for f in norm_*.mp4; do echo "file '$f'" >> concat_list.txt; done
ffmpeg -f concat -safe 0 -i concat_list.txt -c:v libx264 -crf 18 -preset medium -c:a aac final_walkthrough.mp4

### 8. Upload and deliver
- Use upload_file to get a public URL for final_walkthrough.mp4
- Use update_entities to save final_video_url on the Property record
- Use update_entities to set Property status to "Delivered"
- Send the student the download link via chat

## Notes
- Default crossfade: 0.5 seconds
- Always normalize before stitching (mismatched clips produce garbage)
- Clean up temp files after upload
- If a clip is missing or corrupted, tell the student which scene's clip is missing so they can re-upload
- For more than 5 clips, prefer the concat fallback method as the xfade filter chain gets very complex
