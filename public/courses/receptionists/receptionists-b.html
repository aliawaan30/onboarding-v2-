# Receptionist Booking Backend

## What this skill is for

An AI receptionist needs somewhere to put a booking before it can take one. This
skill builds that place. You build it first, every time, because the voice agent's
tools need real working URLs the moment they are attached. Building the agent first
and the backend second is the single most common way this build breaks.

You build four things inside the owner's Base44 app:

1. The **Booking** entity, the table every booking lands in.
2. The **booking_api** function, the one endpoint the voice agent calls.
3. The **inbound_call_router** function, which tells Retell which agent answers.
4. The **retell_webhook** function, which receives call events after each call.

## Parameters you need before you start

Ask the owner for these and never assume them. Everything in this skill that looks
like `{THIS}` is filled in from the answers.

- `{APP_NAME}` the Base44 app you are building inside.
- `{APP_URL}` the app's live base URL, for example `https://your-app.base44.app`.
  You read this off the app itself. Never reuse a URL from an example.
- `{CLIENT_TIMEZONE}` the IANA timezone of the client's business, for example
  `Australia/Brisbane`. This is the client's timezone, not yours, not the server's.
- `{OPEN_TIME}` and `{CLOSE_TIME}` the hours bookings can be made in.
- `{SLOT_MINUTES}` how long one booking slot is.
- `{SERVICE_LIST}` the services the business books.
- `{RETELL_API_KEY}` stored in the app's secrets, never pasted into a page or a
  prompt in plain text.

If you do not have one of these, ask one short question and wait. Do not invent a
default.

## Rule zero: the server decides

Write this down and keep it true through the whole build.

- The agent talks.
- The knowledge base knows.
- **The server decides.**

Every date, every validation, every "is that slot free", every write to the
database happens in `booking_api`, in code, on the server. The language model
never resolves a date, never checks a calendar, never decides whether a booking is
valid. If you find yourself putting that logic in a prompt, stop and put it here
instead.

## Part 1: the Booking entity

Create an entity called `Booking` with exactly these fields:

- `name` (text) the caller's full name
- `phone` (text) the caller's phone number
- `address` (text) where the job is
- `date` (text) the resolved booking date in `YYYY-MM-DD`
- `time` (text) the booking time in 24 hour `HH:MM`
- `service` (text) what they need done
- `status` (choice: pending, confirmed, completed, cancelled. Default: pending)

Optional fields, add them only if the owner asks:

- `notes` (text) anything else the caller said
- `urgency` (choice: routine, urgent, emergency)
- `call_id` (text) the Retell call this booking came from

Read the field list back to the owner before you move on.

## Part 2: the booking_api function

One backend function, two actions. The voice agent's two tools both point at it.

### Action: check_availability

Input: `date` (a string that may be the literal word `today`, the literal word
`tomorrow`, a weekday name, or a `YYYY-MM-DD` date).

What the server does, in this order:

1. Resolve the date. Take the current time in `{CLIENT_TIMEZONE}`. If the input is
   `today`, that is today's date in that timezone. If it is `tomorrow`, add one
   day. If it is a weekday name, take the next occurrence of that weekday. If it
   is already `YYYY-MM-DD`, use it as given.
2. Reject the past. If the resolved date is before today in `{CLIENT_TIMEZONE}`,
   return an error that says the date has already gone and asks for another day.
   Never write a past booking.
3. Build the day's slots from `{OPEN_TIME}` to `{CLOSE_TIME}` in `{SLOT_MINUTES}`
   steps.
4. Remove any slot that already has a Booking on that date with status `pending`
   or `confirmed`.
5. Return the resolved date and a short list of free times. Two or three options
   is plenty. A voice agent reading out fourteen times is unusable.

### Action: create_booking

Input: `name`, `phone`, `address`, `date`, `time`, `service`.

What the server does, in this order:

1. Resolve `date` exactly the way `check_availability` does. Same code path, not
   a copy.
2. Reject the past, same rule.
3. Check the slot is still free. If it is not, return the next two free times so
   the agent can offer them instead of failing.
4. Check for a duplicate first: same name, same date, same time already saved
   means the caller repeated themselves or the agent retried. Return the existing
   booking instead of writing a second row.
5. Create the Booking row with status `confirmed`. The agent confirms with the
   caller on the phone, so there is no pending step in V1.
6. Return a short confirmation with the resolved date and time in words the agent
   can say back, for example `Thursday the 11th at 2pm`.

### The message field is the steering wheel

Every response `booking_api` returns carries a `message` field, and that message
is not for the caller. It is the next instruction to the voice agent. `Booked:
Sarah tomorrow at 2pm. Read it back once, mention the callout fee, then wrap up`
tells the agent exactly what to do next. `No slots left on that day. Offer the
next day` steers it out of a dead end. Write every message as an instruction to
the agent, never as a raw data dump, and the conversation stays on rails even
when things go wrong.

### The date rule, stated once so nobody is confused

The agent is told, in its tool descriptions, to pass the caller's words: the
literal word `today`, the literal word `tomorrow`, or a weekday name. The server
turns that into a real date. This exists because a voice model has no idea what
today's date is and will happily guess a date two years in the past. Every date
lands on the server or it is wrong.

### Signature verification

Retell signs every custom tool request with HMAC-SHA256 and sends it in the
`X-Retell-Signature` header. `booking_api` verifies that signature against the
Retell API key held in the app's secrets, and rejects anything that fails. Do this
before you read the body. Anyone who finds the URL can otherwise write bookings
into the client's database. Implement the check per Retell's current signature
docs and prove it with a real call: one call that books successfully WITH
verification on is the test. `[VERIFY: confirm the exact signature format against
docs.retellai.com before a client build goes live.]`

### Reference implementation, shaped by a live build

The code below is the working shape from a receptionist that took real bookings
on real phone calls. Use it as the skeleton and fill every `{PLACEHOLDER}` from
the owner's answers. The parts that earn their keep: the date resolver that
accepts the literal words the agent passes, the time normaliser that survives
"9am" and "midday", the duplicate check, the spoken-friendly times, and error
responses that always return HTTP 200 with an instruction in `message` (a non-200
makes the voice agent stall mid-call).

```typescript
import { createClientFromRequest } from 'npm:@base44/sdk@0.8.31';

// booking_api - the one endpoint the voice agent calls.
Deno.serve(async (req) => {
  const headers = { 'Content-Type': 'application/json' };
  try {
    let body: any = {};
    try { body = await req.json(); } catch { /* empty body */ }
    console.log('booking_api name:', body.name, 'args:', JSON.stringify(body.args));

    const toolName = body.name || body.tool_name || '';
    const args = body.args || body.parameters || {};

    const TIMEZONE = '{CLIENT_TIMEZONE}';            // e.g. 'Australia/Brisbane'
    // Every bookable time from {OPEN_TIME} to {CLOSE_TIME} in {SLOT_MINUTES} steps.
    const SLOTS = ['07:00','08:00','09:00','10:00','11:00','12:00',
                   '13:00','14:00','15:00','16:00','17:00'];
    const DEFAULT_SERVICE = '{most common service from SERVICE_LIST}';
    const WRAP_NOTE = '{one line the agent mentions while wrapping up}';

    const base44 = createClientFromRequest(req);

    // Today's date where the CLIENT is, as YYYY-MM-DD ('en-CA' formats ISO-style).
    const todayLocal = (): string =>
      new Date().toLocaleDateString('en-CA', { timeZone: TIMEZONE });

    const normaliseDate = (raw: string): string => {
      if (!raw) return '';
      const s = String(raw).trim().toLowerCase();
      const today = todayLocal();
      if (s === 'today' || s === 'now' || s === 'tonight') return today;
      if (s === 'tomorrow' || s === 'next day' || s === 'tmr') {
        return new Date(new Date(today + 'T12:00:00Z').getTime()
          + 24 * 3600 * 1000).toISOString().slice(0, 10);
      }
      const WEEKDAYS = ['sunday','monday','tuesday','wednesday','thursday','friday','saturday'];
      const wd = WEEKDAYS.indexOf(s.replace(/^next /, ''));
      if (wd >= 0) {
        const t = new Date(today + 'T12:00:00Z');
        const diff = ((wd - t.getUTCDay()) + 7) % 7 || 7;
        return new Date(t.getTime() + diff * 24 * 3600 * 1000).toISOString().slice(0, 10);
      }
      if (/^\d{4}-\d{2}-\d{2}/.test(s)) return s.slice(0, 10);
      const parsed = new Date(raw);
      if (!isNaN(parsed.getTime())) {
        const iso = parsed.toISOString().slice(0, 10);
        return iso < today ? '' : iso;
      }
      return '';
    };

    // "9am", "9:00 AM", "midday" -> "09:00"
    const normaliseTime = (raw: string): string => {
      if (!raw) return '';
      const s = String(raw).trim().toLowerCase();
      if (s === 'midday' || s === 'noon') return '12:00';
      const m = s.match(/^(\d{1,2})(?::(\d{2}))?\s*(am|pm)?/);
      if (!m) return '';
      let h = parseInt(m[1], 10);
      const mins = m[2] || '00';
      if (m[3] === 'pm' && h < 12) h += 12;
      if (m[3] === 'am' && h === 12) h = 0;
      if (h < 0 || h > 23) return '';
      return `${String(h).padStart(2, '0')}:${mins}`;
    };

    // "14:00" -> "2pm", because the agent says these out loud
    const spoken = (t: string): string => {
      const h = parseInt(t.slice(0, 2), 10);
      return h === 12 ? '12pm' : h < 12 ? `${h}am` : `${h - 12}pm`;
    };

    const DATE_HELP = "Ask the caller which day, then pass the literal word "
      + "'today' or 'tomorrow', a weekday name, or a YYYY-MM-DD date. "
      + "Never guess dates yourself.";

    if (toolName === 'check_availability') {
      const date = normaliseDate(args.date || args.booking_date || '');
      if (!date) {
        return new Response(JSON.stringify({ success: false,
          message: `Date missing or in the past. ${DATE_HELP}` }),
          { status: 200, headers });
      }
      let bookedTimes: string[] = [];
      try {
        const existing = await base44.asServiceRole.entities.Booking.filter({ date });
        bookedTimes = (existing || [])
          .filter((b: any) => b.status === 'pending' || b.status === 'confirmed')
          .map((b: any) => b.time);
      } catch (e) { bookedTimes = []; }
      const available = SLOTS.filter((s: string) => !bookedTimes.includes(s));
      return new Response(JSON.stringify({
        success: true, date,
        available_slots: available,
        available_slots_spoken: available.map(spoken),
        message: available.length > 0
          ? `Slots open on ${date}: ${available.slice(0, 3).map(spoken).join(', ')}. Offer two or three, not the whole list.`
          : `No slots left on ${date}. Offer the next day.`,
      }), { status: 200, headers });
    }

    if (toolName === 'create_booking') {
      const name = args.name || args.first_name || 'Customer';
      const phone = args.phone || 'caller ID (on call record)';
      const address = args.address || '';
      const date = normaliseDate(args.date || args.booking_date || '');
      const time = normaliseTime(args.time || args.booking_time || '');

      if (!address || !date || !time) {
        return new Response(JSON.stringify({ success: false,
          message: `Booking blocked. Missing or invalid: `
            + `${!address ? 'address ' : ''}${!date ? `date (${DATE_HELP})` : ''}`
            + `${(!date && !time) ? ' and ' : ''}${!time ? 'time' : ''}. `
            + `Get these from the caller, then try once more.` }),
          { status: 200, headers });
      }

      try {
        // Duplicate check: same name, date and time already saved = do not double-book
        let existing: any = null;
        try {
          const dupes = await base44.asServiceRole.entities.Booking.filter({ date, time, name });
          existing = (dupes || [])[0];
        } catch (e) { /* ignore */ }

        if (existing && existing.status === 'confirmed') {
          return new Response(JSON.stringify({
            success: true, booking_id: existing.id, name, date, time,
            message: `Already booked: ${name} on ${date} at ${spoken(time)}, `
              + `${existing.address}. Read it back once and wrap up.`,
          }), { status: 200, headers });
        }

        const created = await base44.asServiceRole.entities.Booking.create({
          name, phone, address,
          service: args.service || DEFAULT_SERVICE,
          date, time, status: 'confirmed',
        });

        return new Response(JSON.stringify({
          success: true, booking_id: created?.id, name, date, time,
          message: `Booked: ${name} on ${date} at ${spoken(time)}, ${address}. `
            + `Read it back once, ${WRAP_NOTE}, then wrap up.`,
        }), { status: 200, headers });
      } catch (e) {
        console.log('create error:', String(e));
        return new Response(JSON.stringify({ success: false,
          message: 'Booking system temporarily unavailable. Do not retry more '
            + 'than once. Say someone will call back to confirm.' }),
          { status: 200, headers });
      }
    }

    return new Response(JSON.stringify({ success: false,
      message: `Unknown tool: ${toolName}` }), { status: 200, headers });
  } catch (e) {
    console.log('endpoint error:', String(e));
    return new Response(JSON.stringify({ success: false,
      message: 'Tool endpoint error.' }), { status: 200, headers });
  }
});
```

## Part 3: the inbound_call_router function

Retell calls this when a call arrives on the number, before the agent starts
speaking. It returns which agent answers and any variables that agent should know.

- Input: Retell's inbound call payload, which includes the caller's number.
- Output: the agent id to use, plus any dynamic variables the greeting needs, for
  example `{BUSINESS_NAME}` and today's date in `{CLIENT_TIMEZONE}`.
- Keep it fast and boring. If it errors, the call fails.

## Part 4: the retell_webhook function

Retell posts call events here: `call_started`, `call_ended` and `call_analyzed`.

For V1, receive all three, verify the signature the same way `booking_api` does,
and log them so the owner can see what happened on a call. `call_analyzed` carries
the post-call analysis fields, which is where the call summary lives.

### CallLog entity, designed now, built later

The design is here so it is ready when the owner wants reporting. Do not build it
unless they ask.

- `call_id` (text) the Retell call id
- `call_date` (text)
- `duration_seconds` (number)
- `caller_phone` (text)
- `outcome` (choice: booking, message, transfer, question, other)
- `summary` (text) from the post-call analysis
- `disconnection_reason` (text)

When it exists, `retell_webhook` writes one row per `call_analyzed` event and the
owner gets per-client monthly reporting for free.

### Reference implementation for the webhook

The canonical shape, reconstructed from the same live build. For V1 without the
CallLog entity, keep the entity write commented out and the console log in: the
function still proves calls are landing. Always return 200, even on errors,
because Retell retries on anything else and a retry storm on a broken handler is
miserable to debug.

```typescript
import { createClientFromRequest } from 'npm:@base44/sdk@0.8.31';

Deno.serve(async (req) => {
  const headers = { 'Content-Type': 'application/json' };
  try {
    const raw = await req.text();
    let event: any = {};
    try { event = JSON.parse(raw); } catch { /* ignore */ }

    const eventType = event.event_type || event.event || '';
    const call = event.call || event;
    const callId = call.call_id || event.call_id || '';
    console.log('retell_webhook event:', eventType, 'call:', callId);

    const base44 = createClientFromRequest(req);

    if (eventType === 'call.ended' || eventType === 'call_analyzed'
        || event.call_analysis || event.post_call_analysis) {
      const analysis = event.post_call_analysis || event.call_analysis || {};
      try {
        // Upsert by call_id: read first, then create or update
        const existing = await base44.asServiceRole.entities.CallLog.filter({ call_id: callId });
        const payload = {
          call_id: callId,
          agent_id: call.agent_id || '',
          direction: call.direction || '',
          from_number: call.from_number || '',
          to_number: call.to_number || '',
          duration_seconds: call.call_cost?.duration_seconds ?? 0,
          disconnection_reason: call.disconnection_reason || '',
          call_summary: analysis.call_summary || '',
          caller_name: analysis.data?.caller_name || '',
          caller_number: analysis.data?.caller_number || call.from_number || '',
          booking_made: analysis.data?.booking_made ?? false,
        };
        if ((existing || []).length > 0) {
          await base44.asServiceRole.entities.CallLog.update(existing[0].id, payload);
        } else {
          await base44.asServiceRole.entities.CallLog.create(payload);
        }
      } catch (e) {
        console.log('CallLog write failed:', String(e));
        // Still return 200 so Retell does not retry-storm
      }
    }

    return new Response(JSON.stringify({ received: true }), { status: 200, headers });
  } catch (e) {
    return new Response(JSON.stringify({ received: true, error: String(e) }), { status: 200, headers });
  }
});
```

## What this V1 does NOT do

- **No SMS.** Do not build, promise or mention a text message to the caller or to
  staff. On an Australian number that needs a Twilio regulatory bundle and a
  messaging permission that are not in place. The Booking entity is the source of
  truth: the owner checks bookings in the app, or asks their co-founder agent for
  the day's bookings. SMS is the first upgrade once the paperwork clears, not part
  of V1. `[VERIFY: SMS dispatch is blocked pending the Twilio regulatory bundle.]`
- **No calendar.** Google Calendar and platform booking APIs are a later tier. The
  entity is the calendar in V1.
